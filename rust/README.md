# kiln for Rust

Rust bindings to kiln: chat, decision, embedding, speech-to-text and text-to-speech models on
the device, through llama.cpp and whisper.cpp.

There are two crates:

- **`kiln-sys`**: the raw C functions from `include/kiln/kiln.h`, generated by bindgen. Every
  call is `unsafe`. Its build script compiles libkiln.
- **`kiln`**: a safe API on top. Models and contexts free themselves, errors are `Result`s
  carrying kiln's message, streamed text comes to a closure, and a [`CancelHandle`] stops a
  call from another thread.

**Where it was run:** Linux x86_64 only (Ryzen 5 8500G, Ubuntu, Rust 1.99), on 2026-10-15. The
11 model tests passed there with the same models as the C suite. macOS, Windows, Android and
iOS were **not built or run**. The build script has link lines for macOS, but nobody has tried them.
It is not on crates.io yet (see [Publishing](#publishing)).

## Use it

The crates live in this repository, so depend on them by path or git:

```toml
[dependencies]
kiln = { git = "https://github.com/RaihanulHaque/kiln" }
```

```rust
use kiln::{ChatOptions, ContextParams, Message, Model, ModelParams, Sampling};

let model = Model::load("models/Qwen3.5-0.8B-Q4_K_M.gguf", &ModelParams::default())?;
let mut ctx = model.context(&ContextParams::default())?;

let mut history = vec![Message::user("What is the capital of France?")];
let stats = ctx.chat(&history, &ChatOptions::default(), &Sampling::default(), |piece| {
    print!("{}", piece.text);   // piece.channel: Answer or Reasoning
    true                        // false stops the reply
})?;
println!("\n{} tokens at {:.1} tok/s", stats.generated_tokens, stats.gen_tps);
```

For the next turn, push the reply and the new question onto `history` and call `chat` again
with the whole list. kiln reuses the part of the conversation already in its cache
(`stats.cached_tokens` shows how much).

The other kinds of model:

```rust
// speech to text (Whisper or Parakeet: no projector needed)
let t = ctx.transcribe_collect(&Media::path("clip.wav"), &TranscribeOptions::default())?;

// embeddings: similarity of two normalised vectors is their dot product
let q = ctx.embed("when does the train leave", &EmbedOptions::query())?;

// text to speech: load the model, then its projector, then make the context
let mut tts = Model::load("pocket-tts-en.gguf", &ModelParams::default())?;
tts.load_projector("mmproj-pocket-tts-en.gguf", &ProjectorParams::default())?;
let mut ctx = tts.context(&ContextParams::default())?;
let speech = ctx.speak_collect("Hello there.", &SpeakOptions { voice: Some(Media::path("voice.wav")), ..Default::default() })?;

// decision models: a probability per answer, in one pass
let d = ctx.decide(Some("my parcel never came"), &question)?;
```

`examples/chat.rs` is a small terminal chat:

```bash
cd rust && cargo run --release --example chat -- ../models/Qwen3.5-0.8B-Q4_K_M.gguf
```

## Things to know

- **Every call blocks** until it is done. In a GUI or an async program, run it on its own thread
  (`std::thread::spawn` or `tokio::task::spawn_blocking`). The closures run on that same thread.
- **Text pieces are whole characters.** kiln's C callback can split a character such as "é"
  across two tokens. The binding holds the first half back and sends the character with the second.
- **A `Model` can serve several `Context`s**, also from different threads (`Model` is `Send + Sync`).
  A `Context` is one conversation and is used by one thread at a time. Load a projector
  (`load_projector`, which takes `&mut Model`) before you create contexts.
- **A panic inside a closure** stops the generation, comes back out of the call, and leaves the
  context usable.
- **Debug builds are still fast where it matters**: llama.cpp is always compiled in Release,
  whatever cargo profile you build with.

## Build

The first `cargo build` compiles llama.cpp and whisper.cpp through CMake, which takes 1 to 2
minutes on an 8-core desktop. It needs CMake and a C++17 compiler, and the submodules
(`git submodule update --init --recursive`). The result is linked statically, so the program
needs no `libkiln.so` at run time.

Two environment variables change this:

| variable | effect |
|---|---|
| `KILN_LIB_DIR=build/host` | link the `libkiln.so` already built there instead of compiling (the program then needs it at run time, e.g. `LD_LIBRARY_PATH`) |
| `KILN_SOURCE_DIR=/path/to/kiln` | build from another kiln checkout |

On Linux, llama.cpp's OpenMP comes from GCC's libgomp, the same as for the C library.

## Tests

```bash
scripts/fetch_models.sh --media --speech     # from the repository root, once
cd rust && cargo test --release
```

`tests/models.rs` runs the same models as `kiln-tests`. It covers chat (streaming, greedy
repeats, cache reuse, stopping), cancelling from another thread, a panic in the closure,
thinking, the decision model, text and image embeddings, Whisper and Parakeet, and Pocket TTS.
The Pocket TTS audio is read back by Parakeet. A test whose model is missing prints `SKIP`.
`KILN_MODELS=<dir>` points at another models folder.

Checked against the C side on the Ryzen: the decision model gives P(yes) = 0.996 for the
refund question and the embedding scores are 0.921 / 0.513, the same as `kiln-cli`.

## After changing `kiln.h`

1. `scripts/gen_rust_bindings.sh` regenerates `kiln-sys/src/bindings.rs` (needs
   `cargo install bindgen-cli`), the same way ffigen does for Flutter.
2. Update the safe wrapper in `kiln/src/` for the new fields or functions.
3. Bump `version` in `rust/Cargo.toml` with the rest. A unit test fails if it differs from
   `KILN_VERSION_*`.

## Publishing

Not done yet. crates.io builds a crate from the files inside it, but `kiln-sys` builds from
the repository around it (`../..`). Publishing means copying a trimmed llama.cpp and whisper.cpp
into the crate, as `scripts/vendor_flutter.sh` does for pub.dev, and keeping the crate under
crates.io's 10 MB limit. llama.cpp alone is 179 MB on disk with everything in it, so this needs
measuring first.
